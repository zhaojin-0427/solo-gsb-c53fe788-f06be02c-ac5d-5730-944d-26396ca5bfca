# 双区烘箱曲线试算 Web 应用

使用 Python、FastAPI、SQLite、Z3 与原生 JavaScript 实现。应用会为两个温区、各自两种响应系数共四条轨迹寻找同一条共享设定温度曲线，并自动保存每次试算快照。

## 一键启动

要求已安装 Docker 与 Docker Compose v2：

```bash
docker compose up --build -d
```

启动后访问：

- Web 页面：<http://localhost:8000>
- 健康检查：<http://localhost:8000/api/health>
- 快照列表 API：<http://localhost:8000/api/snapshots>

页面中选中一条“约束无解”快照后，结果面板会出现“无解原因诊断”区块，点击“运行诊断”即可调用诊断接口并展示极小冲突约束组；已保存的诊断会在重新打开该快照时自动显示。

停止服务：

```bash
docker compose down
```

SQLite 数据库保存在宿主机 `./data/oven.db`，容器内路径为 `/data/oven.db`。

## 输入参数

- 试算时长：1～24 分钟。
- 相邻分钟设定温度最大跃变：0～300℃ 的非负整数。
- 两个温区的整数初温：0～300℃。
- 每个温区两种响应系数 α：0.01～1.00，最多两位小数。
- 每个温区录入：
  - 终温闭区间；
  - 全程温度上限（含初温与每分钟末温度）；
  - 热暴露阈值；
  - 非负最低累计热暴露。
- 共享设定温度：0～300℃ 整数。
- 相邻分钟设定温度跃变：不超过给定非负整数。
- 可锁定任意分钟的设定温度；留空表示不锁定。

## 数学模型

对每个温区、每种系数，从初温开始按分钟精确递推：

\[
T(t+1)=T(t)+\alpha\bigl(U(t)-T(t)\bigr)
\]

其中：

- \(U(t)\) 是第 \(t\) 分钟共享设定温度，为 0～300 的整数；
- \(T(t)\) 为分钟末实际温度；
- 第 \(t\) 分钟末热暴露增量为 `max(0, T(t) - 阈值)`；
- 全程热暴露量是各分钟末增量之和。

所有四条轨迹必须同时满足：

1. 初温及每个分钟末温度不超过温区全程上限；
2. 最终温度位于终温闭区间；
3. 累计热暴露达到最低要求；
4. 设定温度范围、相邻跃变和锁定值要求。

优化目标按严格优先级排列：

1. 最小化设定温度总和；
2. 在总和相同的曲线中，按分钟序最小化 \(U(1), U(2),\ldots,U(N)\)。

Z3 模型使用整数设定温度与有理数温度/热暴露变量。后端在取得模型后，还用 Python `Fraction` 重新独立递推和校验，避免浮点误差。

## 求解状态与 10 秒限时

每次求解的 Z3 总限时为 10 秒，页面明确区分：

- **已证明最优**：找到可行曲线，并完成两级字典序最优性证明；
- **找到可行曲线，尚未证明最优**：已找到并校验曲线，但限时内未完成最优性证明；
- **约束无解**：Z3 证明不存在满足全部约束的曲线；
- **尚未找到曲线**：限时内未取得可行候选，不代表约束一定无解。

## 页面结果

页面会为每种温区和响应系数展示逐分钟表格：

- 分钟；
- 设定温度；
- 实际温度；
- 距全程上限的约束余量；
- 本分钟末热暴露增量；
- 累计热暴露。

表格顶部还展示终温距区间两端的余量、热暴露达标余量和最小全程温度余量。鼠标悬停数值可查看精确分数及精确有限小数值。

每次点击“开始试算”都会保存一条快照，包含原始输入、状态、耗时、曲线和全部轨迹余量。可从右侧快照列表重新载入。

## 无解原因诊断

对状态为“约束无解”的快照，可以进一步诊断哪几组约束共同导致无解：

- 服务仅从快照保存的 `request_json` 还原输入（与当前页面表单无关），并按原精确 Z3 模型重建全部约束。
- 始终有效的约束：设定值整数性、温度递推与非负性、热暴露正部定义。
- 可开关约束组按固定顺序排列：全部设定值的 0～300℃ 范围（一组）→ 全部相邻跃变上限（一组）→ 按分钟递增的每条锁定（每条一组）→ 按输入温区顺序，各温区全部轨迹的全程上限、终温区间、最低热暴露（各一组）。
- 诊断从全集开始按序试删：仅当剩余约束组仍被 Z3 证明无解时才删除该组，最终得到“仍无解、且删去任一组即有解”的极小冲突子集。
- 返回内容包含极小冲突子集、每组的名称与关联轨迹或位置，以及从最终子集逐组删除后得到的可行性见证曲线（不以全集删组的结果代替）；每条见证都用 Python `Fraction` 独立精确校验。
- 诊断过程中的全部 Z3 重跑共用 10 秒预算；未决或超时不保存任何部分诊断并返回错误。

诊断结果独立保存在 SQLite 的 `diagnoses` 表中，可随时重看。

### 诊断接口示例

```bash
# 对“约束无解”快照运行诊断（成功时保存并返回诊断）
curl -X POST http://localhost:8000/api/snapshots/1/diagnose

# 重看该快照最近一次已保存的诊断
curl http://localhost:8000/api/snapshots/1/diagnosis
```

诊断响应包含：`core`（极小冲突组 id 列表）、`groups`（全部可开关组及其 `in_core` 标记、关联轨迹/位置 `detail`）、`witnesses`（从最终子集逐组删除得到的可行设定曲线）、`elapsed_ms` 与 `checks`（求解次数）。

错误情况：快照不存在返回 404；快照不是“约束无解”或重跑与无解结论不一致返回 409；快照缺少可还原输入返回 422；10 秒共享预算内未决或超时返回 504（不保存部分诊断）。

## 本地非 Docker 运行（可选）

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 主要接口

- `POST /api/solve`：提交参数并求解；
- `GET /api/snapshots`：查看最近 50 条快照；
- `GET /api/snapshots/{id}`：读取单条快照完整结果；
- `POST /api/snapshots/{id}/diagnose`：对“约束无解”快照运行无解原因诊断并保存；
- `GET /api/snapshots/{id}/diagnosis`：读取该快照最近一次已保存的诊断。
